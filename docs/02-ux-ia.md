# 前端信息架构与页面设计

## 1. PC C 端

### 1.1 导航

推荐左侧栏：

- 概览
- 抖音账号
- 好友与火花
- 任务
- 发送记录
- 通知
- 设置

右上角：当前用户、权益状态/到期时间、帮助、退出。

当前 PC C 端 MVP 采用 `reference/tinyship-main/apps/tanstack-app` 的应用壳：
顶部 sticky 全局导航、窄内容容器和统一 Card 分区；管理端在同一应用内使用 `/admin/*` 侧栏布局。
导航项在窄屏下保持单行横向滚动，避免压缩为不可读的多行菜单。

### 1.2 概览页 `/dashboard`

核心目标：用户 10 秒内知道“今天是否正常”。

内容：

- 已绑定账号数；
- 有效 / 过期 / 暂停账号数；
- 今日待发送 / 已成功 / 已失败；
- 下一次计划执行时间；
- 最近风险提示；
- 快速入口：绑定账号、同步好友、立即执行；
- 每个账号一张状态卡。

账号卡：

- 头像、昵称、抖音号；
- Session 状态；
- 启用任务数；
- 今日发送数；
- 最近一次同步；
- 下一次任务；
- “进入账号”按钮。

### 1.3 抖音账号页 `/accounts`

列表字段：

- 头像 / 昵称；
- 账号状态；
- 登录态；
- 已管理好友数；
- 今日发送；
- 风险状态；
- 最近检查时间。

操作：

- 添加账号；
- 重新登录；
- 检查登录态；
- 同步好友；
- 暂停所有任务；
- 解除绑定。

### 1.4 绑定账号流程 `/accounts/new`

MVP 仅 PC 扫码：

1. 创建 Binding Job；
2. 页面进入“二维码准备中”；
3. 后端返回二维码事件；
4. 用户抖音 App 扫码；
5. 页面显示“已扫码 / 等待确认 / 登录成功”；
6. 成功后创建 `DouyinAccount`；
7. 自动触发首次好友同步。

整个流程使用 SSE 或 WebSocket，不轮询大量 HTTP 接口。

### 1.5 账号详情 `/accounts/:id`

Tab：

- 概览
- 好友
- 任务
- 记录
- 登录与能力

“登录与能力”展示：

- 登录状态；
- Consumer Web 能力；
- Creator Web 能力；
- Protocol 能力；
- 上次验证时间；
- 最近错误。

### 1.6 好友与火花 `/friends`

筛选：账号、任务状态、火花状态、关键词。

表格：

- 头像；
- 备注/昵称；
- 抖音号；
- 火花天数；
- 是否已有会话；
- 火花维护开关；
- 今日状态；
- 最后发送；
- 操作。

好友的内部身份必须由 `platform_user_id` / `conversation_id` 驱动，前端不需要展示内部 ID。

批量操作只允许：

- 批量开启/关闭已有好友的维护；
- 批量设置时间窗口；

不提供任意好友批量私信入口。

当前 M2 页面已实现账号切换、昵称/抖音号搜索、火花状态与任务状态筛选、好友同步和单好友火花开关。
批量维护与时间窗口编辑留到任务配置模块，且仍需遵守上述批量操作边界。

### 1.7 任务页 `/tasks`

任务模型保持简单：

- 账号；
- 好友；
- 每日启用；
- 发送时间窗口；
- 文本或模板；
- 最近执行；
- 今日状态；
- 启停。

编辑抽屉：

- 时间窗口，例如 19:30–22:30；
- 内容；
- 是否允许首聊（高风险能力，默认关闭）；
- 保存。

当前 M3 页面已实现账号/好友任务列表、关键词与状态筛选、创建/编辑抽屉、每日启停和立即执行。
`/history` 已实现账号、好友、状态、日期和关键词筛选，以及发送记录详情抽屉；任务 API 当前只返回配置本身，不在任务页虚构执行结果。

### 1.8 发送记录 `/history`

字段：

- 时间；
- 账号；
- 好友；
- 任务；
- 通道；
- 状态；
- 错误码；
- 平台消息 ID（用户侧可隐藏）。

详情抽屉展示完整执行时间线：

`scheduled → started → adapter_selected → sent/failed`

当前实现使用 `GET /send-intents` 列表与 `GET /send-jobs/:id` 诊断信息；列表优先展示任务摘要，已删除任务回退到任务 ID。时间线由已持久化的 scheduled、started、adapter 和 finished 字段还原，平台消息 ID 不在用户界面展示。

### 1.9 通知 `/notifications`

通知优先级：

1. 账号登录失效；
2. 安全验证 / 限流；
3. 连续失败暂停；
4. 今日任务执行完成；
5. 系统维护。

当前 V1.1 站内通知已接入 `GET /api/v1/notifications`、`POST /api/v1/notifications/{id}/read` 和 `POST /api/v1/notifications/read-all`。风险事件中的登录失效、安全验证、平台限流和 Adapter/浏览器能力异常会为账号所有者生成通知；同一账号同一风险码在同一 `Asia/Shanghai` 自然日内去重，通知不展示 Session、Cookie 或风险详情 JSON。通知页保留加载、失败、空数据、未读数量、单条已读和全部已读状态。

### 1.10 权益与兑换 `/entitlement`

展示当前有效权益、到期时间、账号槽位、任务额度和功能列表，并提供卡密输入框。

页面只负责兑换授权，不出现价格、购买、订单、支付方式或退款入口。权益过期后，用户仍可进入系统查看历史和兑换新卡，但新绑定、任务启用与发送能力进入只读/暂停状态。

## 2. 微信小程序

小程序定位为“移动控制台”，而不是完整复制 PC。

### TabBar

- 首页
- 火花
- 记录
- 我的

### 2.1 首页

- 今日成功 / 待处理 / 失败；
- 账号状态卡；
- 下一次任务；
- 风险提醒；
- “立即执行”入口。

当前 M4 首页已接入 Taro 请求层与本地 access token：登录后并行加载当前用户、账号、任务和当日发送记录；未登录、token 失效、无账号、无任务和接口失败均有独立状态。页面沿用移动控制台的卡片、状态色和 CTA 语义，但不直接复用 PC DOM 组件。

### 2.2 火花

按账号切换好友列表：

- 头像 + 昵称；
- 火花天数；
- 今日状态；
- 维护开关。

当前 M4 火花页已接入账号切换、好友列表、火花维护开关和每日任务启停；好友与任务开关均以服务端确认结果更新，接口失败保留原状态并显示错误。暂无好友时提示先在 PC 端同步，未配置任务时只展示引导，不伪造可编辑任务。

点击好友进入任务设置：

- 开关；
- 时间窗口；
- 消息内容；
- 最近发送记录。

### 2.3 记录

按日期展示：

- 成功；
- 失败；
- 跳过；
- 需要人工处理。

当前 M4 记录页已接入 `GET /send-intents`，默认按本地日期查询并提供最近 7 天切换；移动端将待处理、排队、执行中和等待重试归为“处理中”，将跳过与取消归为“跳过/取消”，同时展示账号、好友、任务摘要、通道和错误码。执行时间线等诊断详情继续由 PC 端记录详情承载。

### 2.4 我的

- 账号与绑定信息；
- PC 端登录二维码/绑定码；
- 通知设置；
- 权益状态、到期时间与卡密兑换；
- 帮助与协议。

### 2.5 小程序登录

使用微信身份作为一个 `AuthIdentity`，不直接把微信 OpenID 当业务 User 主键。

首次进入：

- `wx.login()` 获取 code；
- 后端换取微信身份；
- 若未绑定产品账号，允许：
  - 新建用户；或
  - 输入 PC 端生成的一次性绑定码，将微信身份绑定到现有 User。

MVP 中抖音账号首次绑定仍推荐在 PC 完成。小程序对未绑定账号显示“请在 PC 完成首次绑定”。

当前实现已接入 `wx.login()`、微信登录、PC 一次性绑定码和本地退出登录交互；后端尚未配置真实微信 AppID/Secret 时，接口明确返回 `WECHAT_NOT_LINKED`，小程序提示用户先在 PC 端完成绑定，不伪造登录成功。

## 3. PC 管理后台

实现决策（2026-08）：参考 `reference/tinyship-main/apps/tanstack-app`，将 Admin 与 PC C 端合并为单一 `apps/web` TanStack App。普通用户页面使用现有顶层路由，管理页面统一放在 `/admin/*` 嵌套路由并由角色守卫保护；两者共用组件库、主题、登录态和构建产物。该决策接受管理员代码进入同一 bundle 的体积取舍，换取统一路由、主题和发布边界。

导航：

- 运营概览
- 用户
- 抖音账号
- 任务与发送
- 风险中心
- Worker / 队列
- Adapter / Capability
- 权益与卡密
- 站点设置
- 审计日志

### 3.1 运营概览

- DAU / 活跃用户；
- 有效账号数；
- 今日发送成功率；
- 失败码 Top；
- 风险账号数；
- Queue latency；
- Worker 在线数；
- Browser/Protocol 成功率。

当前实现由管理员只读接口 `GET /api/v1/admin/overview` 一次返回上述核心指标：DAU 使用 `auth_sessions.last_seen_at` 按 `Asia/Shanghai` 自然日去重，今日发送与失败码/通道成功率使用同一自然日边界；有效账号定义为绑定状态 `bound` 且 Session 状态 `valid`，风险账号定义为 `risk_status != normal`。队列积压、活动任务、重试数和最大观测延迟来自 Asynq runtime，Worker 在线数来自各 Worker pool 心跳。页面复用统一 Admin 壳、Card/Table、主题和响应式断点，并覆盖加载、失败、空数据和手动重载状态。

### 3.2 用户管理

- 用户基础信息；
- 角色；
- 状态；
- 当前权益与有效期；
- 账号/任务额度使用情况；
- 最近登录；
- 授权时间线；
- 禁用/恢复；
- 审计记录。

管理员默认不可以查看抖音 Session 明文。

当前 M5 用户管理已接入管理员只读 API：展示用户角色、状态、账号数、任务数、最近 Web/Admin 登录和权益到期时间，并保留加载、失败、空数据和手动重载状态；列表不返回 Session、Cookie 或其他敏感凭据。用户行可进入授权管理，查看授权时间线并执行带原因的人工 Grant/Revoke。

### 3.3 抖音账号管理

- 所属用户；
- 昵称；
- Session 状态；
- Risk 状态；
- Capability；
- 今日发送；
- 最近错误；
- 暂停/恢复。

当前 M5 已接入管理员账号汇总与暂停/恢复：统一 Web Admin 页面通过角色保护的 API 展示账号归属、绑定/Session/Risk 状态、Capability 快照、今日成功/失败发送和最近风险错误，并保留加载、失败、空数据与手动重载状态；管理员暂停/恢复会写入 `audit_logs`，冷却期未结束时拒绝恢复。

### 3.4 Worker / 队列

- API/Worker 版本；
- Playwright Sidecar 版本；
- Protocol Sidecar 版本；
- 在线心跳；
- 队列长度；
- 运行中 Job；
- 失败 Job；
- Browser slot 使用情况。

当前 M5 已接入管理员只读运行时汇总：通过 Asynq Inspector 展示 interactive/browser/light pool 在线状态、活动 Worker 与并发，展示队列 pending/active/retry/延迟和最近 24 小时失败 Job，并结合 PostgreSQL lease 与 Scheduler leader 状态展示运行概况；构建版本和 Sidecar 版本在运行时尚未上报时显示“未上报”。

### 3.5 Adapter 页面

展示的是“平台接入健康度”，不是内部 Cookie：

- `douyin.browser.consumer`: healthy/degraded/down
- `douyin.browser.creator`: healthy/degraded/down
- `douyin.protocol.im`: healthy/degraded/down

支持管理员临时关闭某个 Adapter，业务层自动选择其余可用能力。

当前 M5 已接入管理员 Adapter 健康页：统一 Web Admin 通过 `/admin/adapters` 展示
browser.consumer、browser.creator、protocol.im 的健康、版本、失败次数、熔断和最近检查状态；
`PATCH /admin/adapters/{adapter}` 只允许管理员启停已登记 Adapter，启停动作写入 `audit_logs`。
未产生过探针记录时显示“未上报”，不把缺少健康记录误判为故障。

### 3.6 风险中心

展示风险事件的账号、所属用户、分类、错误码、严重度、来源 Adapter、动作、冷却时间和发生时间；支持按分类、严重度和错误码筛选。风险列表不展示 `detail_json`，避免将 Session、Cookie 或消息正文带入管理员页面。

当前 M5 已接入管理员只读风险列表：`GET /admin/risks` 支持上述筛选，返回账号与风险摘要，并对分类和严重度做白名单校验。

### 3.7 权益与卡密

子页面：

- 权益方案；
- 卡密批次；
- 兑换记录；
- 用户授权。

卡密批次支持选择权益方案、有效天数、数量、兑换时间窗，生成后一次性导出明文。数据库只保存卡密 HMAC，不提供“找回原卡密”。管理员可以停用批次、撤销未使用卡密、为用户人工 Grant/Revoke，并且所有操作写审计日志。

当前 M5 已接入权益方案、卡密批次、兑换记录和用户授权的统一 Admin 页面：方案与批次支持创建、停用和统计，批次详情可按指纹查看卡密状态并撤销未使用卡密，兑换记录仅返回卡密指纹与授权状态；用户详情支持按方案和天数人工 Grant，并要求填写原因后 Revoke。新生成的明文卡密只在当前页面会话中显示并支持一次性 CSV 导出，刷新后不可恢复。

### 3.8 审计日志

按时间倒序展示操作者、动作、资源类型、脱敏资源 ID、详情是否存在和发生时间；支持按动作、资源类型和操作者检索。原始 `detail_json` 不在普通管理员页面返回，卡密、请求上下文等敏感信息只保留在受控存储中。

当前 M5 已接入管理员只读审计检索：`GET /admin/audit-logs` 支持上述筛选，并统一将详情显示为“已脱敏”状态。
