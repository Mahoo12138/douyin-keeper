# 前端信息架构与页面设计

## 1. PC C 端

### 1.1 导航

推荐左侧栏：

- 概览
- 抖音账号
- 好友与火花
- 任务
- 发送记录
- 通知
- 设置

右上角：当前用户、权益状态/到期时间、帮助、退出。

当前 PC C 端 MVP 采用 `reference/tinyship-main/apps/tanstack-app` 的应用壳：
顶部 sticky 全局导航、窄内容容器和统一 Card 分区；右上角用户菜单展示当前用户和管理员
控制台入口；管理端在同一应用内使用 `/admin/*` 侧栏布局。窄屏下主导航
收纳为可键盘操作的折叠菜单，保持触控目标和退出入口可见，不把所有导航压缩成横向滚动条。
普通用户设置页 `/settings` 展示账号信息、微信服务通知偏好和登录隐私边界；微信通知只有在
小程序完成订阅授权后才能开启，Web 端支持关闭已开启的偏好，站内通知始终保留。

### 1.2 概览页 `/dashboard`

核心目标：用户 10 秒内知道“今天是否正常”。

内容：

- 已绑定账号数；
- 有效 / 过期 / 暂停账号数；
- 今日待发送 / 已成功 / 已失败；
- 下一次计划执行时间；
- 最近风险提示；
- 快速入口：绑定账号、同步好友、立即执行；
- 每个账号一张状态卡。

当前统一 Web `/dashboard` 已并行读取用户、权益、账号、任务、当日发送记录和通知：展示
有效/过期/暂停账号统计、今日待处理/成功/失败、下一次计划、最近风险、账号摘要和绑定/同步/
立即执行入口；当日统计按 `Asia/Shanghai` 自然日查询。右上角用户菜单同时展示权益方案与到期
时间，未激活权益会引导用户兑换。

当前统一 Web `/accounts/:id` 已实现账号详情路由：提供概览、好友、任务、记录、登录与能力五个
Tab；概览展示账号状态与今日发送统计，好友 Tab 可调整火花维护开关，任务/记录 Tab 复用当前
账号数据，登录与能力 Tab 展示能力快照和最近检查时间。详情页的会话检查与好友同步复用 Job
事件 SSE 等待器，支持断线续传、终态错误码和超时清理，并在完成后刷新相关数据。

账号卡：

- 头像、昵称、抖音号；
- Session 状态；
- 启用任务数；
- 今日发送数；
- 最近一次同步；
- 下一次任务；
- “进入账号”按钮。

### 1.3 抖音账号页 `/accounts`

列表字段：

- 头像 / 昵称；
- 账号状态；
- 登录态；
- 已管理好友数；
- 今日发送；
- 风险状态；
- 最近检查时间。

操作：

- 添加账号；
- 重新登录；
- 检查登录态；
- 同步好友；
- 暂停所有任务；
- 解除绑定。

当前统一 Web 账号页已接入会话检查、好友同步、暂停/恢复任务和解除绑定；解除绑定会软删除
账号、停用其任务、取消后续未执行 Intent，并撤销账号 Session，不展示或保留平台凭据。
账号列表接口同时返回好友数、启用任务数和 `Asia/Shanghai` 当日成功/失败发送数，列表直接展示
这些运营摘要；好友与任务统计排除软删除数据，发送统计按发送时间落在产品自然日内的 Intent 计算。
账号列表默认加载 50 条，使用统一 cursor 和“加载更多账号”；任务、好友、会话、历史和账号详情
中的账号选择会继续读取后续页面，避免账号数量增长后选择器只看到第一页。

### 1.4 绑定账号流程 `/accounts/new`

PC 支持扫码和短信验证码两种绑定方式：

1. 用户选择绑定方式；
2. QR 流程进入“二维码准备中”，SMS 流程输入手机号；
3. 后端通过 SSE 返回二维码或 `sms_code_required` 事件；
4. 用户扫码，或输入收到的 4–8 位验证码；
5. 页面显示“已扫码 / 等待验证码 / 验证中 / 登录成功”；
6. 成功后创建 `DouyinAccount`；
7. 自动触发首次好友同步。

整个流程使用 SSE 或 WebSocket，不轮询大量 HTTP 接口。

当前 Web 已将该流程落在独立的 `/accounts/new` 页面：账号列表保留快捷入口，页面复用同一套 QR/SMS
绑定组件，处理 SSE 重连、扫码/验证码状态和取消操作。绑定成功后服务端在事务中创建首次好友同步任务，
前端刷新账号列表并返回账号中心。

### 1.6 好友与火花 `/friends`

筛选：账号、任务状态、火花状态、关键词。

表格：

- 头像；
- 备注/昵称；
- 抖音号；
- 火花天数；
- 是否已有会话；
- 火花维护开关；
- 今日状态；
- 最后发送；
- 操作。

好友的内部身份必须由 `platform_user_id` / `conversation_id` 驱动，前端不需要展示内部 ID。

批量操作只允许：

- 批量开启/关闭已有好友的维护；
- 批量设置时间窗口；

不提供任意好友批量私信入口。

当前 M2 页面已实现账号切换、昵称/抖音号搜索、火花状态与任务状态筛选、好友同步和单好友火花开关。
页面同时支持选择当前筛选结果中的已解析好友，批量开启/关闭火花维护；批量时间窗口编辑复用已有
任务 PATCH 契约，只更新已存在任务，不为未配置任务的好友隐式创建任务。未解析身份的好友不能被选中
开启维护，前后端都遵守上述批量操作边界。好友列表遵循统一游标分页，默认加载 50 条、最多 100 条，
前端通过“加载更多”继续读取，不把大账号的全部好友一次性塞入页面。

独立会话页 `/conversations` 复用同一套账号切换、筛选、表格/移动卡片和主题组件，展示
对端昵称、身份解析状态、消费端/创作者通道、最近消息时间和最近同步时间。页面只消费
后端已经持久化的会话索引；对端显示名仅用于展示和诊断，不能替代平台身份作为发送目标。
当前会话索引由好友同步结果写入，用户侧会话列表遵循统一游标分页，默认加载 50 条、最多 100 条，
通过“加载更多”继续读取后续页面；独立 `conversations.list` Sidecar 分页同步留给真实
平台 selector 稳定后接入。会话支持“未归档/已归档/全部”筛选和单条归档/恢复；归档是
产品侧会话索引状态，不宣称已改变抖音平台侧会话状态。

### 1.7 任务页 `/tasks`

任务模型保持简单：

- 账号；
- 好友；
- 每日启用；
- 发送时间窗口；
- 文本或模板；
- 最近执行；
- 今日状态；
- 启停。

编辑抽屉：

- 时间窗口，例如 19:30–22:30；
- 内容；
- 是否允许首聊（高风险能力，默认关闭；需要 `creator_first_message` 权益）；
- 保存。

当前 M3 页面已实现账号/好友任务列表、关键词与状态筛选、创建/编辑抽屉、每日启停和立即执行。
任务列表遵循统一游标分页，默认加载 50 条、最多 100 条，前端通过“加载更多”继续读取，
避免大账号任务一次性加载全部数据。
`/history` 已实现账号、好友、状态、日期和关键词筛选，以及发送记录详情抽屉；任务 API 当前只返回配置本身，不在任务页虚构执行结果。
任务编辑器会并行读取当前权益：无首聊权益时禁止打开未开启的首聊开关，但允许已有任务关闭该配置；
后端创建、编辑与发送执行仍会再次校验，前端不作为安全边界。

消息模板池 `/templates` 提供当前用户自己的文字/贴纸模板 CRUD，模板名称最多 80
字符、内容最多 500 字符；任务编辑抽屉提供“从模板套用”，只复制当前内容，不建立
隐式联动，后续修改模板不会改变已有任务。列表默认按更新时间加载 50 条，使用统一
cursor 分页和“加载更多模板”；任务编辑抽屉也可继续加载模板，避免模板池过大时截断选择。

### 1.8 发送记录 `/history`

字段：

- 时间；
- 账号；
- 好友；
- 任务；
- 通道；
- 状态；
- 错误码；
- 平台消息 ID（用户侧可隐藏）。

详情抽屉展示完整执行时间线：

`scheduled → started → adapter_selected → sent/failed`

当前实现使用 `GET /send-intents` 列表与 `GET /send-jobs/:id` 诊断信息；列表优先展示任务摘要，已删除任务回退到任务 ID。时间线由已持久化的 scheduled、started、adapter 和 finished 字段还原，平台消息 ID 不在用户界面展示。记录列表默认按 `id DESC` 加载 50 条，使用统一 cursor 和“加载更多记录”读取后续结果；账号、好友、状态和日期筛选会随分页请求保持不变。

### 1.9 通知 `/notifications`

通知优先级：

1. 权益即将到期；
2. 账号登录失效；
3. 安全验证 / 限流；
4. 连续失败暂停；
5. 今日任务执行完成；
6. 系统维护。

当前 V1.1 站内通知已接入 `GET /api/v1/notifications`、`POST /api/v1/notifications/{id}/read` 和 `POST /api/v1/notifications/read-all`；通知列表遵循统一游标分页，默认加载 50 条、最多 100 条，前端通过“加载更多”继续读取；通知偏好通过 `GET/PATCH /api/v1/notifications/preferences` 管理。权益剩余 7 天、3 天、1 天时由 Scheduler 为账号所有者生成幂等到期提醒；风险事件中的登录失效、安全验证、平台限流和 Adapter/浏览器能力异常也会生成通知，同一账号同一风险码在同一 `Asia/Shanghai` 自然日内去重，通知不展示 Session、Cookie 或风险详情 JSON。通知页保留加载、失败、空数据、未读数量、单条已读和全部已读状态；微信通知通过事务性 outbox 与 `worker-light` 异步投递，权益到期提醒只保留站内展示，失败状态可重试且不影响站内通知。

### 1.10 权益与兑换 `/entitlement`

展示当前有效权益、到期时间、账号槽位、任务额度和功能列表，并提供卡密输入框。

页面只负责兑换授权，不出现价格、购买、订单、支付方式或退款入口。权益过期后，用户仍可进入系统查看历史和兑换新卡，但新绑定、任务启用与发送能力进入只读/暂停状态。
当前页面同时展示用户自己的授权历史：包含方案、来源、起止时间和有效/待生效/已过期/已撤销
状态；历史接口只返回脱敏授权字段，不返回完整卡密或其他用户数据，默认加载 50 条并通过
“加载更多授权记录”继续读取。

### 2.5 小程序登录

使用微信身份作为一个 `AuthIdentity`，不直接把微信 OpenID 当业务 User 主键。

首次进入：

- `wx.login()` 获取 code；
- 后端换取微信身份；
- 若未绑定产品账号，允许：
  - 新建用户；或
  - 输入 PC 端生成的一次性绑定码，将微信身份绑定到现有 User。

MVP 中抖音账号首次绑定仍推荐在 PC 完成。小程序对未绑定账号显示“请在 PC 完成首次绑定”。

当前实现已接入 `wx.login()`、服务端 `jscode2session` 身份交换、微信登录、PC 一次性绑定码、本地退出登录、“微信服务通知”订阅授权，以及权益状态/到期时间、最近兑换记录展示和 DK1 卡密兑换；兑换成功后立即刷新当前权益与记录，记录支持继续加载，失败保留输入状态并展示错误。后端未配置完整的微信 AppID/Secret 时，接口明确返回 `WECHAT_IDENTITY_NOT_LINKED`，小程序提示用户先在 PC 端完成绑定，不伪造登录成功。服务端只保存 `wechat_mini` 的 provider subject，不持久化微信 `session_key`。

## 3. PC 管理后台

实现决策（2026-08）：参考 `reference/tinyship-main/apps/tanstack-app`，将 Admin 与 PC C 端合并为单一 `apps/web` TanStack App。普通用户页面使用现有顶层路由，管理页面统一放在 `/admin/*` 嵌套路由并由角色守卫保护；两者共用组件库、主题、登录态和构建产物。该决策接受管理员代码进入同一 bundle 的体积取舍，换取统一路由、主题和发布边界。

导航：

- 运营概览
- 用户
- 抖音账号
- 任务与发送
- 风险中心
- Worker / 队列
- Adapter / Capability
- 权益与卡密
- 站点设置
- 审计日志

### 3.1 运营概览

- DAU / 活跃用户；
- 有效账号数；
- 今日发送成功率；
- 失败码 Top；
- 风险账号数；
- Queue latency；
- Worker 在线数；
- Browser/Protocol 成功率。

当前实现由管理员只读接口 `GET /api/v1/admin/overview` 一次返回上述核心指标：DAU 使用 `auth_sessions.last_seen_at` 按 `Asia/Shanghai` 自然日去重，今日发送与失败码/通道成功率使用同一自然日边界；有效账号定义为绑定状态 `bound` 且 Session 状态 `valid`，风险账号定义为 `risk_status != normal`。队列积压、活动任务、重试数和最大观测延迟来自 Asynq runtime，Worker 在线数来自各 Worker pool 心跳。页面复用统一 Admin 壳、Card/Table、主题和响应式断点，并覆盖加载、失败、空数据和手动重载状态。

### 3.2 用户管理

- 用户基础信息；
- 角色；
- 状态；
- 当前权益与有效期；
- 账号/任务额度使用情况；
- 最近登录；
- 授权时间线；
- 禁用/恢复；
- 审计记录。

管理员默认不可以查看抖音 Session 明文。

当前 M5 用户管理已接入管理员 API：列表与详情展示用户角色、状态、账号数、任务数、最近 Web/Admin 登录和权益到期时间，并保留加载、失败、空数据和手动重载状态；列表不返回 Session、Cookie 或其他敏感凭据。用户详情支持禁用/恢复：禁用事务性撤销该用户全部 Web/Admin/小程序会话与 Refresh Token，并写入审计日志；恢复不会复活旧会话，用户需重新登录。用户详情同时展示按资源 ID 过滤的脱敏审计时间线，不开放原始 `detail_json`。用户行可进入授权管理，查看授权时间线并执行带原因的人工 Grant/Revoke。用户列表默认加载 50 条，使用统一 cursor 和“加载更多用户”。

### 3.3 抖音账号管理

- 所属用户；
- 昵称；
- Session 状态；
- Risk 状态；
- Capability；
- 今日发送；
- 最近错误；
- 暂停/恢复。

当前 M5 已接入管理员账号汇总与暂停/恢复：统一 Web Admin 页面通过角色保护的 API 展示账号归属、绑定/Session/Risk 状态、Capability 快照、今日成功/失败发送和最近风险错误，并保留加载、失败、空数据与手动重载状态；管理员暂停/恢复会写入 `audit_logs`，冷却期未结束时拒绝恢复。管理员账号列表默认加载 50 条，使用统一 cursor 和“加载更多账号”。

### 3.4 Worker / 队列

- API/Worker 版本；
- Playwright Sidecar 版本；
- Protocol Sidecar 版本；
- 在线心跳；
- 队列长度；
- 运行中 Job；
- 失败 Job；
- Browser slot 使用情况。

当前 M5 已接入管理员只读运行时汇总：通过 Asynq Inspector 展示 interactive/browser/light pool 在线状态、活动 Worker 与并发，展示队列 pending/active/retry/延迟和最近 24 小时失败 Job，并结合 PostgreSQL lease 与 Scheduler leader 状态展示运行概况；构建版本和 Sidecar 版本在运行时尚未上报时显示“未上报”。

Generic Job 明细已独立接入 `/admin/jobs`：管理员可按状态和 Job 类型筛选并通过统一 cursor
查看绑定、同步和会话检查的生命周期元数据；页面不展示事件 payload、Session、Cookie 或消息正文。

### 3.5 Adapter 页面

展示的是“平台接入健康度”，不是内部 Cookie：

- `douyin.browser.consumer`: healthy/degraded/down
- `douyin.browser.creator`: healthy/degraded/down
- `douyin.protocol.im`: healthy/degraded/down

支持管理员临时关闭某个 Adapter，业务层自动选择其余可用能力。

当前 M5 已接入管理员 Adapter 健康页：统一 Web Admin 通过 `/admin/adapters` 展示
browser.consumer、browser.creator、protocol.im 的健康、版本、失败次数、熔断和最近检查状态；
`PATCH /admin/adapters/{adapter}` 只允许管理员启停已登记 Adapter，启停动作写入 `audit_logs`。
未产生过探针记录时显示“未上报”，不把缺少健康记录误判为故障。

### 3.6 风险中心

展示风险事件的账号、所属用户、分类、错误码、严重度、来源 Adapter、动作、冷却时间和发生时间；支持按分类、严重度和错误码筛选。风险列表不展示 `detail_json`，避免将 Session、Cookie 或消息正文带入管理员页面。

当前 M5 已接入管理员只读风险列表：`GET /admin/risks` 支持上述筛选，返回账号与风险摘要，并对分类和严重度做白名单校验。风险列表默认加载 50 条，筛选条件随统一 cursor 保持，并通过“加载更多风险”读取后续结果。

### 3.7 权益与卡密

子页面：

- 权益方案；
- 卡密批次；
- 兑换记录；
- 用户授权。

卡密批次支持选择权益方案、有效天数、数量、兑换时间窗，生成后一次性导出明文。数据库只保存卡密 HMAC，不提供“找回原卡密”。管理员可以停用批次、撤销未使用卡密、为用户人工 Grant/Revoke，并且所有操作写审计日志。

当前 M5 已接入权益方案、卡密批次、兑换记录和用户授权的统一 Admin 页面：方案与批次支持创建、停用和统计，批次详情可按指纹查看卡密状态并撤销未使用卡密，兑换记录仅返回卡密指纹与授权状态；用户详情支持按方案和天数人工 Grant，并要求填写原因后 Revoke。新生成的明文卡密只在当前页面会话中显示并支持一次性 CSV 导出，刷新后不可恢复。权益方案、卡密批次、兑换记录、卡密明细和用户授权时间线默认加载 50 条，使用统一 cursor 与“加载更多”读取后续结果；方案与卡密明细按 ID 正序读取，仍不返回明文卡密。

### 3.8 站点设置

站点设置使用受约束的 JSON key/value 形式，支持按键新增或更新站点模块配置；配置键只允许
安全标识符，敏感凭据不得写入。列表和更新均由 Admin 角色保护，更新只在审计日志中记录配置键，
不记录具体配置值。

### 3.9 审计日志

按时间倒序展示操作者、动作、资源类型、脱敏资源 ID、详情是否存在和发生时间；支持按动作、资源类型和操作者检索。原始 `detail_json` 不在普通管理员页面返回，卡密、请求上下文等敏感信息只保留在受控存储中。

当前 M5 已接入管理员只读审计检索：`GET /admin/audit-logs` 支持动作、资源类型、资源 ID 和操作者筛选，并统一将详情显示为“已脱敏”状态。审计列表默认加载 50 条，筛选条件随统一 cursor 保持，并通过“加载更多审计记录”读取后续结果。
